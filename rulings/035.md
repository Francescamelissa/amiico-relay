§1 — do not push to test this. Read first.

.husky/pre-push is a file. Open it, and .husky/_/pre-push with it, and say whether the ancestry-based non-fast-forward refusal is anywhere in that chain. That is free, instant, side-effect-free, and it answers the content question outright. Only if the guard is in the chain does anything need to be pushed at all — and then only to prove invocation, not existence.

§2 — the test you proposed cannot distinguish the two outcomes

Work through it. If you push normally, a fast-forward is permitted by an active guard and by an absent one alike — the observation is identical under both hypotheses, so it carries no information. If instead you push something the guard is meant to refuse, and the guard is inert, the remote history is rewritten and you find out by inspecting the wreckage.

So the proposal is uninformative in the safe case and destructive in the informative one, and there is no third case. A test that cannot fail is not a test; you have to see the guard refuse something, which is the demonstrated-red discipline you already applied correctly to RED 2.

And one refinement to the rule you were leaning on, because I think it is what led you here. Verifying the artefact afterwards is how you detect what happened. It is not permission to take the action. Checking the remote after a push tells you what you did; it does not tell you whether you should have done it — a detection mechanism used as an authorisation mechanism is how irreversible things get done carefully and still get done wrongly.

§3 — the test that works, when you get to it

Create a branch that exists only to be destroyed — scratch/hook-test, from anywhere. Push it normally and confirm it lands. Then rewrite it locally so the next push is genuinely non-fast-forward, and attempt that push. An active guard refuses; an inert one lets it through, and the only casualty is a branch whose entire purpose was to be the casualty. Then delete it, remote and local.

The blast radius of a test must be the test's own subject. Nothing that matters should be able to learn anything about itself from this experiment.

Report the reading from §1 before running §3. If the guard turns out not to be in the husky chain, then it has been inert for however long core.hooksPath has pointed there, every push in that window went unguarded, and installing it correctly comes before testing it — with the same scratch-branch proof afterwards.
