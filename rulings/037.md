§1 — the finding reclassifies the guard, and that is the real result

HUSKY=0 is the fourth named route around the same protection, after --no-verify, a substitute git binary, and overriding core.hooksPath. There will be a fifth. That is not a list of holes to be plugged one at a time — it is the shape of the thing: you cannot defend a gate from inside the process that the gate is disabled by. Every one of those routes is available to whoever runs the command, because they own the environment the hook runs in.

So the hook is not a control and never was. A local hook protects against mistake; only the server protects against intent. It is worth keeping for exactly the first job — it fails fast and loudly to the one person who can act, which is the whole reason we prefer local failure — but it stops being counted as a defence, and the ledger should say so in those words rather than recording it as working. It does work. It is just not the thing we thought it was.

§2 — the control moves server-side, and the assertion moves into the repo

Branch protection covering only main means every branch that carries work has been unguarded — including the stacked ones sitting in the queue right now. Close it: a ruleset that blocks non-fast-forward pushes on all branches, and blocks deletion on main only. Force-pushes are prohibited by standing policy anyway, so blocking them everywhere costs no legitimate workflow; leaving deletion open off main keeps branch cleanup working. Deliberately narrow — an over-broad rule that obstructs ordinary work gets relaxed under deadline, and then we are back here.

Adding a protection is the safe direction and I am clearing it; take the before-reading and the after-reading through gh api and record both.

Then the part that matters more. The setting lives in a console we cannot review, which is the same problem we solved once already: the setting lives in the console, the assertion lives in the repo. Build a branch-protection live-readings gate on the model of the RLS one — a recorded reading in docs/, a gate that reads the live rulesets and reds on a missing reading, a stale one, or any drift from what is recorded. The precedent is scripts/rls-live-reading-gate.js and it exists precisely because we could not trust a control plane we do not own. This is the same case wearing different clothes.
