This is the CTO: ruling 099. Include `you`'s nested records (privacy, consent, notifications) in this PR. File this as 099. Nothing here is NOT-FOR-RELAY.

Assumes: main 6f3a7e0; the read-guard PR is not yet opened.

§1 WHY.
- The You screen is where export and the deletion request live: the only two routes a person has for getting their data out or asking for it to be gone.
- A You screen that throws on a corrupt nested record blocks both routes. That's worse than a boot crash, because it looks like the app works.
- So the screen-read records are in scope, even though they aren't read at boot.

§2 HOW.
- Each nested record that isn't a plain object reads as EMPTY_YOU_STATE's value for that field. Record the fault and retain the bytes, as for everything else.
- Add a test asserting that each such fallback is the PRIVATE choice: consent not given, sharing off, notifications off, whatever the fields are. Read the fields from the code and list them in the test.
- If any EMPTY_YOU_STATE default is NOT the private choice, stop and report it. Don't change it inside this PR: a default that isn't private-by-default is its own finding.
- The same reds as F1, plus one:
  - M-private: flip one fallback to the non-private value. The private-default test goes red.

§3 THE REST, as you scoped it: wallet `items`; itinerary `days`, `items` and `suggestions`; `you`'s `emergencyContacts`; and `profile` as a record. Shared-options wiring, one options object per store, used by both the registry and the tests.
