§A — standing rules while nobody is watching

Work in committed increments. Never finish a unit with uncommitted changes to tracked files — an interruption should cost one unit, not a night. Tonight is the second time that lesson has been available and the first time it was free.

No destructive git anywhere near the main working tree. Build the scratch-tree helper first (item 1) and route every experiment through it. A scratch branch is not a scratch tree.

Nothing touches production. No Supabase dashboard, no SQL editor, no live database, no console settings, no erasure, no App Store Connect. All of it needs her, and none of it is available.

When a decision needs me, write it down and move to the next item. Do not decide it yourself to keep moving. A night of work built on a guess I would have refused is worse than a night with one item parked. Park it in QUEUE.md with the question stated and carry on.

If the composite goes red and you cannot make it green, stop everything and write up. Do not stack work on a red base.

§B — the order of work. Top down; do not skip.

1. The scratch-tree helper (QUEUE row 20). Everything below depends on it. Done when a destructive git operation runs inside a disposable worktree, a fixture proves the main tree is byte-identical afterwards, and the fixture reds if the helper is bypassed.

2. The CI cascade fixture. The single most valuable thing on this list, because it is what makes October safe. A seeded user with a row in every one of the forty places, in the local stack, then private.erase_user, asserting each count goes non-zero → zero — the cascade proven against a populated before-state rather than the empty one production would give us. Assert the tombstone and sentinel behaviour. And assert the four residuals survive, as predictions written into the test: the audit-log entries, the invited email, the free-text summaries, the emergency contact. A test that only checks what disappears cannot catch what shouldn't have.

3. The residual sweep, two tiers, from the catalog. Structural — columns that exist to hold another person's identity or contact details. Incidental — free text that may contain anyone. Two separate lists. For every structural one, say whether erase_user currently handles it. That list is what the notice's erasure sentence gets written against.

4. activity_log.entity_id. The contradiction from 029 §2, answered from the writers: every call site, and the full set of values entity_type can take. If a user id can land there, it is a forty-first place and items 2 and 3 both change.

5. The trip write and delete paths. Three days open. What writes a trips row to the server, given the sync engine's own comment says no network — file and line, and what triggers it. Why trips and nothing else: single-table path, or a general path the children never take. And what deleting a trip in the app actually does. This decides whether the children are broken or unbuilt, and the keying work waits on the answer.

6. home_currency. What writes it and what it is meant to mean, given both Thailand rows hold THB for a user in the United Kingdom. Establish before anything is built on it; a name that lies is worse than a missing column.

7. The two summary-PDF defects. Cities rendering as Mexico City, Mexico City — find whether the duplication is written at entry or rendered from the wrong field, because those have different fixes and only one is cosmetic. And the date range printing with no year on a trip that crosses New Year, while the "Generated on" footer carries one. The document a traveller prints must be readable without knowing when it was made.

8. The push-notifications toggle on the budget screen. It accepts input and nothing is wired behind it. Recommend — wire, disable with a visible reason, or remove — and do not implement the choice. Fifth instance of a promise made in one system about a capability living in another; file it against that parent.

9. The self-retiring DEVELOPER_DIR arm. Both branches demonstrated, driven by pointing the predicate at a working git and a broken one. It fires once, in the future, unattended — which is exactly why it cannot ship untested.

10. The forty-five stale remote refs. Prune. Housekeeping, safe, and it makes the branch readings mean something.

If all ten land: resume activity keying — design and tests only, as a pull request left open, not merged. Per-trip keying is the change that nearly deleted every city she has entered, and it gets read by me before it lands, in daylight.
